2. Decisions only you can make

Settled 14 September 2026, by the product owner: declare non-trader; keep the name Canvas Downloader Connector; publish Public; and replace the popup footer with the wording below. The reasoning behind each is kept so nobody re-opens them without new information.

Trader or non-trader

Every developer must declare one, because of the EU Digital Services Act. A trader acts "for purposes relating to his trade, business, craft or profession"; a non-trader acts outside them. A trader's verified name and contact details are shown to EU users. A non-trader's listing tells EU users that consumer-protection rights do not apply. Google's own FAQ says it is "a legal question. Each publisher must make their own determination", and gives no ruling on donations. The extension is free and has no payments. Whether the Ko-fi link changes that is your call, not something the docs answer.

The name

Canvas Downloader Connector is the manifest name, and the store takes the title from the package. The Microsoft Store rejected "Canvas Downloader" three times for containing another product's name, which is why that channel is Course Downloader for Canvas. The Chrome Web Store has no equivalent mechanical name check. Its policy only forbids implying you are "authorized by, endorsed by, or produced by another company", and many listings named "Canvas …" are live. Keeping the name matches the app, the website and the button copy in the app ("click the Canvas Downloader button"). Renaming would also rename the entry in Chrome's puzzle-piece menu, which the app's instructions point students to.

Public or Unlisted

Public lists it in search. Unlisted installs only from the link, which is all the app needs. Both go through the same review. Public is also a way for students to find the app; Unlisted keeps it quiet while the route is new.

Popup footer wording

The policy requires what the extension handles to be stated plainly, and the old line ("This extension never looks at any pages you visit") sat on the same screen that prints the address of the tab you are on. Replaced, on his word, with:

Popup footer

This extension only works when you click it. It checks that this tab is your Canvas, then passes your Canvas login to the Canvas Downloader app on this computer. Nothing is sent anywhere else.

3. The workflow

  1. Finish the account page. In the developer dashboard, Account: the Google account needs 2-Step Verification before it can publish; set the publisher name (it appears under the title, so BrkBuilds, matching the Microsoft Store and GitHub); verify the contact email (required); make the trader declaration; turn on email notifications. The account's email address can never be changed.
  2. Build the package. python scripts/build_extension_package.py writes installer_output/canvas-downloader-connector-<version>.zip. It refuses if the manifest names a missing file, a script does not parse, or canvas-hosts.js is stale, because each of those has shipped once and a rejected upload costs days.
  3. Add new item and upload the zip. The title, summary and icon come from the package. New publishers are limited to two published extensions.
  4. Store listing tab. Paste from section 4.
  5. Privacy tab. Paste from section 5. This is the tab review reads most closely.
  6. Distribution tab. Free, All regions, and the visibility you chose above.
  7. Test instructions tab. Paste from section 6. A reviewer who cannot make it work can reject under "broken functionality", and this extension does nothing without the app.
  8. Submit for review. Leave "publish automatically" ticked unless you want to release an app update the same day; unticked, you get 30 days to press publish before the submission reverts to a draft.
  9. Wait. Google says most reviews finish in a few days and some take a few weeks. This item hits three of the four listed triggers for a longer review: new developer, new extension, and a sensitive permission (cookies) plus broad host access. Past three weeks, contact developer support.
  10. When approved. Copy the listing URL (https://chromewebstore.google.com/detail/…) into EXTENSION_STORE_URL in ui/auth.py, check the store button on screen (it has never rendered), update the install section of extension/README.md, and ship an app update.
  11. Every later update. Raise version in extension/manifest.json (it must go up), rebuild, Package tab, upload new package, submit. Updates get the same review as a new item.

5. Privacy tab

Single purpose

Signs the Canvas Downloader desktop app in to Canvas using the Canvas login the user already has open in a browser tab, so they do not have to sign in to Canvas a second time inside the app.

Justification: cookies

When the user clicks "Sign me in", the extension reads the Canvas session cookie (canvas_session, or _normandy_session on a self-hosted Canvas) for the one Canvas site the user granted, and passes them to the Canvas Downloader app running on the same computer at http://127.0.0.1. That cookie is how the app signs in to Canvas. No other cookie is read, nothing is read without a click, and nothing is sent anywhere except the local app.

Justification: activeTab

When the user opens the popup, the extension reads the address of that one tab to tell them whether they are on their Canvas site before it offers to sign in. It has no access to any other tab and no "tabs" permission.

Justification: storage

chrome.storage.session holds two short-lived values: the site a sign-in is waiting on while Chrome's permission prompt is open (the prompt closes the popup, so the service worker finishes the sign-in), and whether a sign-in succeeded, so the popup can say so instead of restarting its guide. Session storage is cleared when the browser closes and is not written to disk.

Justification: alarms

Once a minute the service worker asks the Canvas Downloader app on the same computer (http://127.0.0.1) whether it is waiting for a sign-in, so the toolbar icon can show a dot when it is time to click. It contacts nothing else and sends nothing.

Justification: host permission

The host permission is optional and nothing is granted at install. At the user's click, chrome.permissions.request asks for exactly one origin: the Canvas site in the tab they are on. Canvas is hosted on thousands of different school domains, including custom domains, so the origin cannot be listed in advance. The extension never requests any other origin.

Declared as optional_host_permissions. A pattern like *://*/* gets extra scrutiny even when optional, which is why this text says what is requested at runtime.

6. Test instructions tab

Instructions

This extension works together with the Canvas Downloader desktop app (free, open source): https://canvasdownloader.app/ To test: 1. Install and open Canvas Downloader on Windows or macOS. 2. In a Chrome tab, sign in to any Canvas site. 3. In the app's sign-in screen, open "Use the browser extension instead" and click "Sign in with the extension". 4. In the Canvas tab, click the extension icon and choose "Allow access", then "Sign me in". The app then shows the signed-in account's name. Without the app running, the popup shows its guide and says the app is not ready. The extension makes no network request except to http://127.0.0.1 on ports 53127 to 53129, where the app listens only while a sign-in is being asked for.
