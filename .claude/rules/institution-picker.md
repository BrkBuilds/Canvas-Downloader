# The login institution picker

> Extracted from CLAUDE.md. Loads only when Claude opens a matching file.
> Each entry states the mechanism, the measurement, and why the obvious fix is wrong.

## The login institution picker: a shortcut that must never become a gate (2026-08-07)
A searchable directory of Canvas institutions sits to the RIGHT of the "Your Canvas URL" field; picking one writes its address into that field. The field stays fully editable, so the picker is a **shortcut and never a gate** - every one of the thousands of Canvas schools NOT in the list works exactly as before. That framing is load-bearing in the copy: an always-visible caveat under the row, plus an empty state worded as an instruction ("Your school still works"), because a student whose school is missing must not conclude the app does not support them.
- **The most dangerous failure is not a missing school, it is the WRONG one.** Omitting a school costs one extra paste into a field that is right there; a wrong entry hands the student a real, working Canvas login page belonging to a different university, with nothing on screen suggesting the address was the problem. Every gate below is sized by that asymmetry.
- **`scripts/build_institution_list.py` is the generator and the app never talks to Instructure's finder.** The pipeline is crawl (~7,200 published accounts - the hard ceiling; many large universities simply are not discoverable) -> match seeds for clean display names -> fill from the crawl under each account's OWN name -> verify -> hand-review reject list. **The FILL half carries no pairing risk at all**, because nothing is mapped to anything: the account's own name beside its own domain. That is why coverage can be raised without re-auditing pairings, and it is the property the whole widening rests on.
- **THE APP IS NOT UNIVERSITY-ONLY, and the generator used to assume it was (corrected 2026-08-09).** Every institution and every level that uses Canvas is in the target group - erhvervsakademier, VUC, gymnasier, konservatorier, K-12 districts. The old fill gate `_HIGHER_ED` allowed only English/Spanish/Portuguese/German HIGHER-ED words, so it excluded two whole categories at once: every non-university institution, and every institution of any level whose own published name is Nordic, Finnish, Dutch, French or Italian. **Denmark shipped two entries** while Erhvervsakademi Aarhus, Den Danske Filmskole, VUC Roskilde, Det Kgl. Danske Musikkonservatorium and IBA all verified as live Canvas hosts. The gate is now `is_institution()`: an accent-FOLDED multilingual allowlist (`_EDUCATION`), minus things that are not schools or are a school's side entrance (`_NOT_AN_INSTITUTION` - churches, vendors, hospitals, alumni/catalog/continuing-ed/parent tenants), plus `_ACADEMIC_TLD` as standalone proof (`.edu`, `.ac.*`, `.edu.*`, `.sch.*`) for accounts published only as an acronym. **1,797 -> 4,272 rows, and 0 of the old candidates lost - it is a strict superset.**
  - **Only the FILL gate moved. `_BAD_ACCOUNT`, `accepts()`, `contradicts()` and `corroborates()` are untouched**, so no seed pairing can change because of a coverage decision. `tests/test_institution_gate.py` builds the list twice with the fill gate forced wide open and asserts every seed row is identical - that separation is what makes raising coverage safe, and it must not be wired together again.
  - Declined on measurement, do not re-litigate: **domain-side** education-word matching (admits 18 accounts, nine of them Yamaha music schools) and a **blocklist-only** fill gate (+1,939 rows at ~35% junk - Hubspot, franklincovey, a medical-software vendor). The allowlist is what keeps the list trustworthy at 4,272 rows.
- **The SEED ranking needs `domain_rank` as its last key, or a tie is decided by crawl order.** `jaccard` scores token SETS, so "University of Michigan - Ann Arbor", "- Dearborn" and "- Flint" are all exactly 1.00 against the seed, as are "University of Kansas - KU" and "- kuconnect.ku.edu"; corroboration and ccTLD tie with them, and `key > best[0]` then keeps whichever the crawl dict yielded FIRST. Measured 2026-08-09: Michigan resolved to **Dearborn** and Kansas to `kuconnect`. The fix belongs in the seed key, not in the dedupe - that pass already sorts by `domain_rank`, but core rows are ordered ahead of fill rows, so by then the seed's choice is frozen. A tie test that does not feed the pool in the LOSING order passes with the fix removed; `tests/test_institution_gate.py` runs both orders for exactly that reason.
- **`LOCAL_NAMES` must be looked up ACCENT-FOLDED - the two tables disagree about spelling.** `SEEDS` writes "Malmo University", "Umea University", "Linkoping University"; `LOCAL_NAMES` keys the same schools with their accents. A plain `dict.get` therefore returned `None` and those universities shipped with no Swedish name at all - not in the label, and not as a matcher probe, which also means a locally-named account and its English seed read as two different schools. It fails silently: `display_name` just returns the English name, which looks deliberate. `local_name()` folds the key; **8 further `LOCAL_NAMES` entries had no seed at all** and are now seeded, because LOCAL_NAMES is only ever consulted FOR a seed.
- **The shipped data can be AHEAD of the generator.** The pre-2026-08-09 module contained "Högskolan Dalarna (Dalarna University)" and "Technische Universität Nürnberg (...)", which the code at that commit could not reproduce - so a regeneration silently dropped them. After any regeneration, diff against the previous module and explain every REMOVED row before shipping; that diff is what found three of the four defects in this section.
- **Verification is unreliable at scale, and one retry pass is not enough.** A 16-way sweep over ~4,500 domains reported ~180 "genuinely unreachable" hosts, of which 16 sampled by hand answered on the FIRST try individually, every one in under 1.5 s - including the University of Kansas, Georgetown, Rhode Island School of Design and Wake Technical Community College. Retrying the same way reproduces it; `verify_many` now runs gradually gentler passes (16 workers -> 3 -> 1) with a cooldown. **That makes a full rebuild take ~2.7 hours**, almost all of it in the final serial pass over hosts that really are dead. To iterate, feed the previous run's verdicts back as a cache (every shipped domain verified `ok`) and verify only what is new - nothing in the generator changes what a host answers, and it turns a rebuild into ~6 minutes.
- **The three hand-review gates do different jobs and `dedupe_key` can undo one of them.** `REJECT` blocks a seed->domain pairing and DROPS that seed entirely (it does not fall through to the runner-up); `REJECT_DOMAINS` drops a host outright; `RENAME` relabels a real tenant whose own name over-claims. **A RENAME label must not use a parenthetical or a " - " tail**: `dedupe_key` runs `clean_name` again on the finished label, strips the qualifier straight back off, and the row collides with the one it was renamed to be distinct FROM. Measured: `hkust-gz` renamed to "... (Guangzhou)" vanished entirely instead of sitting beside the main campus.
- **A SIMILARITY SCORE CANNOT ANSWER THIS QUESTION - ten wrong universities shipped before that was understood (2026-08-08).** Symmetric scoring above was necessary and not sufficient. "University of British Columbia" vs "Columbia University" scores 0.667, the domain `courseworks2.columbia.edu` genuinely corroborates the shared token, and every gate agreed - because the one word that decides it, **`british`**, is exactly what a score discards. Same shape put **Duke Kunshan on Duke's Canvas, Colorado State on CU Boulder's, Oklahoma State on Oklahoma Christian's, Central Florida on Central State's, North Texas on North Park's, South Carolina on South Alabama's, Manchester Met on the University of Manchester's, UWA on Western Colorado's and American University in Dubai on American University DC's**. All ten were live; a student picking their own school got a real, working login page for a different university with nothing on screen suggesting the address was wrong.
  - **`contradicts()` asks the question a score cannot**: does either name carry a *distinctive* token (non-generic, so not "university"/"state"/"college"/"royal") that the other lacks **and the domain does not vouch for**? A one-sided uncorroborated word is not a spelling variation, it is another school. It must veto **one-sided** - requiring both sides to differ lets `British Columbia -> Columbia University` straight back through.
  - **THE SECOND DEFECT, and the reason rejection alone would have made things worse:** `corroborates()` built the acronym from EVERY word, so "University of Central Florida" produced `uocf` and never `ucf`. **A school whose Canvas host is its own acronym could not corroborate its own domain** (`ucf`, `unt`, `ubc` all failed), so the matcher passed over the RIGHT host and settled for a wrong one that happened to corroborate. Fixing the veto without this would have deleted five real universities instead of repointing them. Corroboration also has to work in **both directions** (`colostate` -> `colo` is a *contraction*, a prefix of the token rather than the reverse), and `.edu` counts as a US country signal because `cc_of` already treats it that way.
  - **A hand-review REJECT keyed on one pairing cannot close the hole.** Four of the ten domains were ALREADY in `REJECT` - for a *different* seed. `northpark` was blocked for "North-West University" and then captured "University of North Texas"; `centralstate` was blocked for "Central European University" and captured "Central Florida". The list is a backstop, never the remedy.
  - **`clean_name` splitting on " - " is its own trap**: `instructure.charlotte.edu` publishes itself correctly as "University of North Carolina - Charlotte", and stripping the tail promoted a correct campus tenant into a claim on the whole system, one row above the real Chapel Hill. That is a `RENAME`, not a rejection - its own students need the entry.
- **The display name is `Local (English)`, and LOCAL_NAMES has a SECOND, invisible job.** A Dane types "Københavns", not "University of Copenhagen"; shipping only English made the picker miss on the first thing its user types. The same table is fed to the matcher as a **probe** (`local_probes`) - without it, an English seed and a locally-named account ("Göteborgs Universitet" vs "University of Gothenburg", which share *no* tokens and score 0.0) read as two different institutions and `contradicts` drops the school. **A display-only change would pass every rendering test and silently lose them.**
  - **Local names then made every Nordic row unreachable from a plain keyboard**, found by driving the running app: `kobenhavn`, `goteborg`, `hogskolan`, `lulea`, `haskolinn`, `nurnberg` each matched **zero** rows. `search_blob` now carries an accent-FOLDED copy beside the original, so a substring test finds the row either way and the bridge needs no change. Fold the HAYSTACK, not the query. `ø`/`æ`/`ß` are letters, not accented forms - NFKD leaves them alone, so they need an explicit map; `å` folds to `aa` (what people actually type) and still matches a `lulea` query by prefix. Known and accepted: an unaccented query finds the row but does not highlight it.
- **Score names SYMMETRICALLY, and never stop "college"/"state"/"university".** Both rules were learned by shipping their violation into a generated list. One-way recall of the seed's tokens scores 1.00 for any account merely CONTAINING the distinctive word - it paired **KTH with RMIT Melbourne, Korea University with Yamaha Music Korea, Cairo University with the American University in Cairo**. Stopping "college"/"state" collapses `University of Florida` and `Florida College` to the same token set - it paired **Boston University with Boston College, UC Berkeley with Berkeley College, and the University of Miami with Miami University (Ohio)**.
- **The domain must corroborate, by whole-LABEL equality or prefix - never substring** (`jesuit` contains `uit` and would vouch for UiT Norway on six high schools). Labels also strip a fused LMS affix, because institutions write `cbscanvas`: without that, **Copenhagen Business School's own domain fails to corroborate its own perfectly-matching name**. Aliases corroborate too - `Absalon` IS what `absalon.instructure.com` is called, and requiring the English seed there dropped Denmark's largest university from a Danish-market build.
- **A contradicting ccTLD is a decisive veto**, and it is the ONLY thing that rejects `Open University` (GB) matching `UTS Open` on `canvas.open.uts.edu.au` - the names genuinely share their one distinctive token.
- **Verification must prove Canvas, not reachability** (`/api/v1/users/self` returning Canvas's own unauthenticated payload): a parked domain, a marketing site and an SSO portal all answer an ordinary request. And **every failure is retried serially before being believed** - a 16-way sweep produced sporadic timeouts that silently deleted CBS, the University of Copenhagen and the University of Melbourne from a build, all three of which verify fine alone. `tests/test_institution_picker.py` pins those exact rows as ANCHORS, so a regeneration that loses a market fails instead of shipping.
- **`ui/institution_picker.py` is hand-built markup, not `st.selectbox`** - a Streamlit widget inside `st.form` cannot rerun, so a native picker could not fill the field until submit, which is the one moment the value is no longer needed.
- **The options are SERVER-rendered and the bridge only reads them.** A `components.html` iframe re-runs only when its srcdoc changes and this one's is constant, so anything the bridge painted would vanish the first time Streamlit re-rendered the markdown and never come back. The mirror image is why the picked label survives: React leaves an unchanged `dangerouslySetInnerHTML` subtree alone across reruns (verified - a full rerun kept the label, the filled URL and the status row).
- **Writing the value takes React's native setter plus `focus()` then `blur()`.** Assigning `.value` does not notify React; `blur()` is a no-op on an unfocused element. Verified end to end in the real app: picking CBS and submitting produced *"Access token needed"*, not *"Canvas URL needed"* - i.e. the value reached Python.
- **Corrected by measurement: `st.form` renders a DIV in 1.51, not a `<form>`** (zero `<form>` nodes on the login page), so a bare button here does not natively submit. `type="button"` and the Enter swallow stay anyway - Streamlit implements Enter-to-submit itself, so an un-swallowed Enter in the picker's search box still fires the login.
- **`match_url` is exact-host only**; a suffix rule would let `evil-harvard.edu` borrow `harvard.edu`'s identity. The live status row does offer a suggestion in the *opposite*, safe direction: typing `harvard.edu` (the main website, a natural mistake that fails at login with a generic error) names OUR verified `canvas.harvard.edu`. It prefers the SHORTEST host under the typed domain - taking the first match pointed Harvard at a pre-college certificate tenant.
- The picker's stylesheet lives in `ui/auth.py`'s login block. **Writing a literal angle-bracket tag name in one of those CSS comments kills the whole login stylesheet** - the architecture audit's Rule 7 caught exactly that while this was being built.
- **At ~1,800 entries the rendering model had to change, and the split is the point: the DATA is server-sent, the ROWS are not.** One button per institution is ~230 KB of markup for React to re-parse on every rerun plus 1,800 live nodes to filter per keystroke. The list now ships as ONE delimited payload on `.cd-inst-list[data-rows]` and the bridge renders only the top `RENDER_CAP` (60) matches. That is safe only because the rows are *derived* - a bridge runs once per mount, so anything it INVENTED would vanish on the next re-render and never come back, while anything it re-derives on open/keystroke cannot go stale. Delimiters are `»`/`«` (never present in a name, and unlike tabs/newlines they survive an attribute untouched); a test proves the shipped data contains neither.
- **`.instructure.com` ships as ONE byte, because rows have to be cheap.** Most tenants have no vanity domain, so those 16 characters repeat once in the domain field and again inside the search blob: measured on the 4,272-row list, 7,844 occurrences, 123 KB, **28% of the payload** - on the login page, which is the slowest screen in the app and the one a user reported hanging. `_SUF_TOKEN` (`*`) replaces it and the bridge's `expand()` restores it on BOTH fields at parse time, so the rendered domain, the `https://` link and the haystack are byte-identical to the uncompressed form; it runs once per mount because `rows()` memoises on the raw attribute. Net effect: **107 -> 79 bytes per row**, so 2.4x the institutions cost 1.7x the payload (187 KB -> 325 KB). `_clean_field` strips the token from names for the same reason it strips the delimiters - a literal `*` in a name would be expanded into `.instructure.com` and corrupt both the label and the search text. **The answer to payload pressure is cheaper rows, never fewer rows**: the picker is how nearly everyone finds their Canvas URL, and typing one by hand is the friction it exists to remove.
- Measured in the real app at 4,272 rows: **4.7-22.4 ms per keystroke**, i.e. unchanged from the ~1,800-row measurements, because `RENDER_CAP` bounds the DOM and the filter is a flat scan. (Re-measured at 4,750 rows WITH scoring and sorting: **3.1-15.8 ms**. See "The picker had no ranking" below - the filter is no longer a bare substring test.)
- **Two measured performance traps, both in the render path.** Compiling the highlight RegExp per ROW cost **55-78 ms per keystroke** (200 identical objects); it is now built once per render. And `scrollIntoView` forces a synchronous layout, so calling it on every render - for a list already scrolled to the top - cost another **35-60 ms**; it now fires only when the KEYBOARD moved the cursor. Final: worst keystroke **22.6 ms**, median 17.8, narrow queries ~5 ms.
- **The keyboard cursor must not be DOM focus.** Arrow keys move an `aria-activedescendant` on the search input, never focus itself, or typing stops working the moment you arrow into the list. The keyboard-active row is painted deliberately stronger than hover (plus a left rail): with a mouse hover and an arrow cursor both on screen, two identical highlights make it impossible to tell what Enter will take.
- **The three hand-review gates are different instruments, and picking the wrong one loses real users.** `REJECT` blocks a seed→domain PAIRING (the wrong-university case) but does NOT stop the fill re-adding that domain under its own correct name - which is right: `canvas.queens.edu` really is Queens University of Charlotte and its students should find it. `REJECT_DOMAINS` drops a host outright, for the AU/IE Catholic secondary schools that "College" cannot distinguish from real US liberal-arts colleges (enumerated, because any regex broad enough to catch `St Aloysius' College` also catches `Saint Anselm College`). `RENAME` is for a real tenant whose self-declared name OVER-claims - the only NYU account the finder publishes is Steinhardt's, named "New York University"; dropping it costs Steinhardt students their entry, so it ships as "New York University (Steinhardt)". **Prefer a rename to a rejection whenever the tenant is real and only the label is wrong.**
- ~~**Country is empty for ~83% of entries and that is not a defect**~~ - **SUPERSEDED 2026-08-09.** It was true while country only widened the search haystack; it stopped being acceptable the moment the picker began OPENING on the user's own country, because a country nobody has costs every user in it that whole feature. `infer_cc` now reads unambiguous markers in the institution's own name where the domain has no ccTLD, taking known countries from 366 to 1,556 (Denmark 2 -> 9). The ccTLD is still PROOF and always wins; a marker only ever speaks for a domain that has none, and the result is still never displayed as a claim about the institution - see below.
- **Three bugs shipped past per-feature verification, and all three lived at a SEAM** (found by the user, 2026-08-07). (a) `knownByHost` read the *rendered* dropdown rows, and closing the dropdown wipes them - so the act of PICKING a school made that school unknown and a freshly-picked Copenhagen Business School reported "Not one of the listed institutions". It reads the payload now. (b) The outside-click branch called `setOpen(false)` on **every click anywhere on the page**, and that focused the trigger - so clicking into the access-token field lit it up and then had focus yanked away a frame later, making the token impossible to type and login unusable. Closing an already-closed picker is now a no-op, and focus is restored only on a DELIBERATE close (Escape, or taking a row); an outside click leaves the caret where the user put it. (c) A `margin-top` written above a `margin` shorthand **in the same block** is silently overwritten - which made a spacing fix look like the CSS was not applying at all.
- **The status line groups with the field ABOVE it, and there is no standing "not listed" caveat.** The caveat now lives only in the picker's empty state, beside the search that came up empty - as a permanent line under the URL field it repeated that text verbatim and hung a "not listed" remark on a perfectly valid, recognised address. The status row itself is its own markdown block, so Streamlit's 1rem flow put 24px above it and 0 below, i.e. visually attached to the NEXT field's label; a single negative-top margin shorthand puts it at a measured 7px above / 12px below.
- **The trigger's label is DERIVED from the URL field, never remembered.** The field is the only truth - the picker exists solely to fill it - and storing the picked name separately let the two drift: clear the field after choosing a school and the picker still named a school the form no longer pointed at. `syncTrigger()` re-derives it from `paintStatus()`, which already fires on every keystroke, on pick and on mount; `pick()` must NOT write the label itself. Deriving it buys the reverse for free - paste a different known school's address by hand and the trigger follows. The default string lives in Python and is read off `data-default-label`, so the markup and the reset cannot disagree.

### The picker had no RANKING, and that was the whole problem (2026-08-09)
`matches()` filtered and returned rows in `DATA` order, which is `(country code, name)`. Everything below follows from that one omission, and all of it was measured in the running app before the fix.
- **What the user saw**: `harvard` answered with *"Harvard Medical School Pre-Med Online Certificate Program"*, `oxford` with *"Said Business School"*, `singapore` with *"National Institute of Early Childhood Development"*, and the picker OPENED on the United Arab Emirates and Australia for everybody on earth.
- **93% of the list was unreachable for a broad query.** 3,963 of 4,272 rows are `*.instructure.com`, which has no ccTLD, so `cc` was `""` and they sorted last under `'ZZ'`. `college` matched 929 rows and `school` 1,486, and a Filipino or Indian student never saw their school in either - the first 60 were always AE/AU/BD alphabetically.
- **The country blob poisoned the haystack.** `COUNTRY_NAMES` text was baked into every row, so `state` matched *"united states"*: **194 of its 322 hits matched nothing else**, and 232 of 535 for `us`. The table now ships ONCE (`country_payload()`) and a country term must match a WHOLE token - prefixes were tried and are wrong, because `state` prefixes `states`.
- **The weights are ORDINAL, not tuned**: whole name > name prefix > word in the name > fragment inside a word > domain > "your country is called this". A **fixed** bonus (seed, home country) must stay smaller than the gap between two adjacent tiers so it can only order near-equals; `test_ranking_weights_keep_their_order` pins that, and it is what stops a re-tune quietly restoring the unranked behaviour.
- **`S_DLAB` sits ABOVE a name prefix on purpose.** A whole domain label equal to the whole query is an institution stating its identity in four characters, and typing that acronym is how people who know their school look it up. Measured with it below the prefix score: `ust` answered with "UST Angelicum College" over the University of Santo Tomas on `ust.instructure.com`, and `tip` with "Tippecanoe School District" over the Technological Institute of the Philippines on `tip.instructure.com`.
- **The coverage bonus is the one signal that separates "contains the word" from "IS the word"** - the fraction of the NAME's own words the query accounted for. It is why "Harvard University" beats "Harvard Medical School Pre-Med Online Certificate Program" without any hand-written preference.
- **Prominence exists because no text score can express "many people mean this one".** `flags == "s"` marks a curated seed. It is NOT a level preference (the product owner ruled 2026-08-09 that K-12 must compete on equal footing) - a school district typing its own name wins on exactness and coverage long before the bonus matters. Without it, `melbourne` answers with Melbourne Grammar School purely because its name starts with the word.
- **A leading article costs a name its prefix bonus.** Canvas accounts are titled inconsistently ("The University of Melbourne" beside "University of Sydney"), and that alone decided the ranking. `article()` strips a leading definite/indefinite article for the prefix test only.
- **Mid-word matching is KEPT, at low weight.** It is what makes `roskilde` find `vucroskilde` and `akademi` find `Erhvervsakademi`; it is also why `unsw` matches "br**unsw**ick County Public Schools". Recall is worth having when ranking decides what is visible.
- **Education-word synonyms are scored LOW and are worth having**: they say what KIND of place this is, never which one. Without them "university jorge" cannot find "Universidade Jorge Amado" and a Dane's "universitet" cannot find an English-named row.

### The opening state, and reading the user's region offline
- Before a key is pressed the picker shows **the institutions in the user's own country**, seeds first, under *"Institutions in Denmark - or type to search all 4,750"*. The region comes from `Intl.DateTimeFormat().resolvedOptions().timeZone` first and `navigator.language` second - **the time zone is asked first on purpose**: it reports where the machine IS, whereas the UI language is a preference, and an English-language Windows is the norm across most of this app's markets. No request is made and nothing is stored.
- Fewer than 5 rows for the region falls back to the curated seeds, which is a better "here is what this is" than an alphabetical slice.
- **The inferred country is never DISPLAYED as a claim about an institution** - it only widens the haystack and orders this list - which is what makes a lower evidence bar correct here than anywhere else in the builder. A wrong guess costs one unexpected row in a suggestion list; a wrong name-to-domain pairing costs a student their university.

### The pairing gates were reasoning about names with the disambiguator already deleted
Nine wrong name-to-domain pairings shipped, each verified against the live finder on 2026-08-09. **`norm_name` splits on `" - "` and strips parentheticals BEFORE every veto runs**, so "University of Tennessee - Martin" arrived as "University of Tennessee" and scored a perfect 1.00 against a seed it is not.
| Shipped as | Domain | What the account really says |
|---|---|---|
| University of South Carolina | `courses.online.usc.edu` | "USC Online" - Univ. of *Southern California* |
| Eotvos Lorand University | `elu.instructure.com` | "ELU - European Leadership University" |
| Universidad de los Andes (CO) | `uandes.instructure.com` | "Universidad de los Andes - **Chile**" |
| University of New South Wales | `canvas.unswcollege.edu.au` | "UNSW **College**" (a pathway provider) |
| University of Arizona | `healtharizona.instructure.com` | "... - College of Public Health" |
| University of Tennessee | `utm.instructure.com` | "... - **Martin**" |
| Western Sydney University | `canvas.westernsydneyonline.edu.au` | "Western Sydney **Online**" |
| University of York | `onlinestudy.york.ac.uk` | the online-study tenant |
| Georgia State University | `robinsongsu.instructure.com` | the Robinson College of Business tenant |
Knock-on: **University of Southern California was missing entirely**, because South Carolina had taken its domain and won the alphabetical dedupe.
- **`tail_of` / `tail_segments` recover what `norm_name` discards**, and there are now TWO questions asked of a tail, deliberately different. `tail_tokens` (broad) answers *"may I delete this from the LABEL?"* - it must stay broad or "University of Tennessee - Martin" becomes a claim on the whole university on the fill path. `qualifier_tokens` (narrow - only a tail carrying an entity-KIND word) answers *"is this a different institution?"*, and the narrowing was forced by measurement: a veto on every unvouched tail rejected "University of Michigan - **Ann Arbor**" while accepting "- **Flint**", because the branch campus names itself in its host and the flagship does not. **It reliably picked the wrong campus of any multi-campus university.** Coupling the two is what re-breaks either one.
- **An entity-KIND word the seed lacks is distinctive**, even though `_GENERIC` drops it from every other comparison. "UNSW College" is not the University of New South Wales, and *College* is the only word that says so.
- **An AMBIGUOUS initialism is not weak evidence, it is none.** `_AMBIGUOUS_ACRONYMS` is COMPUTED from the seed list (never hand-listed, so it cannot go stale) and the initialism branch declines anything in it. Note the test must use a host with no sub-tenant word in it - the shipped USC case is vetoed earlier by `domain_is_subtenant`, so asserting on it alone passes with the guard deleted.
- **A sub-tenant word in the DOMAIN is a veto only when the seed's own name does not contain it** - `online.smc.edu` really is Santa Monica College's Canvas. Declining is self-correcting: the domain falls through to the fill path and ships under the account's own name, so the institution is labelled rather than lost. `_TENANT_NOISE` cannot be reused here - it is written for RANKING, so its alternatives are unanchored and `pd`, `dev` and `prof` match inside ordinary words.
- **A hand-written `RENAME` is consulted BEFORE the name gates, not after.** Re-testing a human's answer with the heuristics they were overriding dropped four real tenants: `clean_name` strips a trailing "Online", which is the only education word "Western Sydney Online" and "USC Online" have.

### The crawl was silently discarding ~40% of every letter
- `crawl()` ran `range(1, 61)`. **The finder has no result cap**: measured by binary-searching the last non-empty page, `a` ends at 94 and `e` at 106. On letter `a` alone, pages 61-94 hold **2,433 domains the crawl never saw, 1,400 of which pass `is_institution`**.
- **a-z + 0-9 is PROVABLY complete**, and that is worth knowing before anyone adds market-specific search terms: the finder substring-matches the DOMAIN as well as the name (`oskilde` finds `vucroskilde.instructure.com`, whose account is named "VUC Roskilde"), so every `*.instructure.com` domain contains "instructure" and the single term `e` returns all 9,542 of them. Full crawl: **7,309 domains, 10,505 account names, ~15 minutes.**
- **A domain publishes SEVERAL names and the crawl kept whichever it reached first** - an artefact of alphabetical search order. 1,770 domains have more than one. `best_account_name` prefers a name carrying an education word over a bare acronym (`tip.instructure.com` shipped as "TIP" rather than "Technological Institute of the Philippines"), then one without an audience qualifier, then the longer.
- **`_BAD_ACCOUNT` is applied per NAME, and a domain is seedable if ANY of its names is clean.** `canvas.lms.unimelb.edu.au` publishes both "The University of Melbourne (non-SSO)" and "The University of Melbourne"; the first matched, so the seed found no candidate at all and Australia's best-known university shipped without its curated name - and, once ranking existed, below Melbourne Grammar School.
- **Verification verdicts are cached between runs, and only `ok` is ever cached.** A failure is the verdict that can be wrong for reasons outside the host, and a cached false negative would delete an institution permanently and identically on every later run. With the cache a rebuild is minutes instead of hours; the final retry pass went 1 worker -> 2, because a serial sweep over ~500 dead hosts at a 30 s timeout IS the runtime of the script.

### Coverage: the finder is NOT the ceiling - CORRECTED the same day
The paragraph that stood here claimed the shipped list was at the source's ceiling, on the strength of 1,529 conventional hostnames (`canvas.<domain>`, `lms.<domain>`, ...) answering zero times for India, South Africa and Nigeria. **That probe had a hole and the conclusion was wrong.** It never tested `<slug>.instructure.com`, which is how most tenants actually run. Re-probed properly:
- **`harvard.instructure.com` answers as Canvas and appears nowhere in the crawl.** The account finder publishes accounts that opted into DISCOVERY; that is a strict subset of the live tenants, and nothing in the pipeline knew it.
- A sweep of ~1,300 plausible slugs found **72 live Canvas hosts**, 26 of them for institutions the list did not have. India went from 1 to 4.
- What survives of the old claim: **the universities themselves mostly do not run Canvas.** UCT, Wits (main), Stellenbosch, Pretoria, UNISA, the IITs, Manipal, VIT, BITS, Ashoka, UNILAG, Ibadan, USP and Unicamp answered on no host, slug or vanity. India's 33 Store installs are not evidence of 33 Indian Canvas institutions - a Store country is where the ACCOUNT is registered, not where the user studies, and Australia (the top market) is full of Indian students.

**THE HARD PART IS NOT FINDING A HOST, IT IS PROVING WHOSE IT IS - and this is where the sweep nearly did real damage.** Of the 72 live hosts, **46 were already in the crawl under names that contradicted the slug guess**:

    rhodes -> Rhodes COLLEGE (Memphis), not Rhodes University ZA   [SSO link: myonelogin.rhodes.edu]
    nwu    -> Northwestern University PHILIPPINES, not North-West ZA
    nu     -> NIHON University (Japan), not National University PH
    lpu    -> Life Pacific University (US), not Lovely Professional IN
    abu    -> Arlington Baptist, not Ahmadu Bello NG
    msu    -> Michigan State, not Mindanao State
    boston -> Boston College UK (EU data region), not Massachusetts

Shipping those guesses would have recreated the wrong-university class **at scale**, on the very day it was eliminated. So `scripts/institution_direct.py` requires EVIDENCE that names the institution, and two unauthenticated signals on the login page provide it:
- the **branding logo's URL**, which keeps the filename the institution uploaded (`Krea Logo-01.jpg`, `logo_usfq_Login.png`, `senac_logo.png`);
- a link to the institution's **own domain** (`sgl.icei.pucminas.br`, `campusvirtual.unitec.edu.co` - the latter proving `unitec` is COLOMBIA, not the Honduran UNITEC the slug suggests);
corroborated by the tenant's **S3 data region** (`apse1` Singapore = India/SEA, `dub` Ireland, unsuffixed us-east-1).
The login `<title>` is useless - it is always "Canvas Login | Instructure". **Roughly 60% of tenants use default branding and publish nothing that names their owner**, and those were all left out: `usp`, `fgv`, `insper`, `mackenzie`, `iie`, `milpark`, `wvsu`, `utec`, `vut`, `stadio`, `cti`, `afe`, `lbs`, `ul`, `apu`, `bennett`, `du`, `gems`, `snu`, `stonehill`, `upes`, `imi`. Missing is recoverable - the user types their address. Wrong is not.

**Do not turn `DIRECT` into a scanner.** The sweep was one-off, bounded and hand-reviewed. The answer to wanting more coverage is more EVIDENCE per candidate, never more candidates.

**A country marker must be unambiguous IN PRACTICE, not merely suggestive.** Three were not, and each put a real institution in the wrong country's opening list: `indian school` (Red Cloud Indian School, Pine Ridge, South Dakota), `islands` (California State University, Channel Islands), `city college of` (City College of San Francisco, twice), plus an unbounded `universiti` matching the English "Universities". `""` is always an acceptable answer; a wrong country is not. Accepted and documented: `hogeschool` covers the Netherlands AND Flanders, and both are Dutch-speaking, so a Flemish school in a Dutch user's list is a miss worth taking.

### Payload: the answer to pressure is cheaper rows, never fewer rows
- The old format shipped `name » domain » blob`, where the blob re-stated the name and domain a second time inside a string only the search read: **169 KB of a 333 KB payload, 51%**. Fields are now `name » domain » cc+flags » folded-name » aliases`, and the bridge reassembles the documented haystack from them - which is exactly what `test_payload_reassembles_exactly_the_documented_haystack` asserts, so `search_blob` stays the single readable definition of "what text finds this row".
- **`cc` is space-PADDED to two characters.** Country is 2 letters or empty and flags are letters too, so an unpadded join is ambiguous precisely when a row has a flag and no country: `"" + "s"` is `"s"`, which reads back as the country `s`. 19 rows were in that state. The test CONSTRUCTS the case rather than looking for it - today every seeded row carries its seed's country, so a test that searched for it would already have stopped testing anything.
- **`SEARCH_ALIASES` is what students CALL their school**, search-only, keyed by domain, and deliberately NOT in the builder's `ALIASES` - a probe there feeds the name MATCHER, so adding "KU" would let the University of Copenhagen lay claim to any host with a `ku` label. Measured before it existed: a Dane typing `ku` got the University of Kansas and not one Danish row, because KU's Canvas is called `absalon` and its name contains no `ku` at all.

**Covered by `tests/test_institution_picker.py` (163) and `tests/test_institution_gate.py` (52); all 18 mutations of the real code are caught, so re-run the mutation pass and not just the suite.** Two hazards cost time here and will again: these two files are **CRLF**, so a multi-line anchor written with `\n` never matches and reads as a missing guard; and a heredoc through this shell mangles backslashes, so write test source with the file tools, not `python - <<EOF`.
