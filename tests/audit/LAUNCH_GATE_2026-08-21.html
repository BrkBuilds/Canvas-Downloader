Done this session

The macOS bundle could ship a broken code signature

fixed

Both specs swept a developer's __pycache__ into the bundle — 75 stale .pyc — and codesign sealed them. Remove any one afterwards and the seal breaks. The two Gatekeeper outcomes are different classes:

valid ad-hoc seal spctl → "rejected" exit 3 __pycache__ removed spctl → "a sealed resource is missing" exit 1

Exit 3 is the not-notarized denial — the dialog with the Open Anyway path your Mac guide walks through. Exit 1 is "is damaged and can't be opened", with no way back. The app ships unsigned by design, so that one recoverable dialog is the macOS onboarding route.

I checked the reachability against the shipped artifact rather than reasoning about it, and it corrected my own severity: the v2.0.1 DMG was downloaded and inspected, and carries one __pycache__ in a third-party licenses folder and none of the app's own. Release DMGs come from a fresh CI checkout, so this never reached a user. Fixed anyway so a local build is byte-comparable to the CI one.

That inspection did find what did ship: v2.0.1's bundle fails codesign --verify because pync vendors a nested app PyInstaller cannot seal. Already fixed — pync is out of the spec and a fresh build verifies exit 0. It still assessed as exit 3, so a failing codesign does not by itself mean "damaged". 9/9 mutations caught, after six survived a first pass and three of those were defects in my own tests.

75% of the homepage and 97% of the guide were invisible without JavaScript

live
