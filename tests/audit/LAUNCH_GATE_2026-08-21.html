Fixed today

The macOS bundle could ship a broken code signature

was shipping

Both specs bundle the app's packages by directory, so PyInstaller swept a developer's __pycache__ into the bundle — 75 stale .pyc — and codesign sealed them. Remove any one of them afterwards and the seal breaks. That is not cosmetic, and it matters because the app ships unsigned:

valid ad-hoc seal spctl -a -t exec → "rejected" exit 3 __pycache__ removed spctl -a -t exec → "a sealed resource is missing" exit 1

Those are different verdict classes. Exit 3 is the not-notarized denial — the "Apple could not verify…" dialog with the Open Anyway path that the whole of mac-setup.html walks a user through. Exit 1 is a signature validity failure: "…is damaged and can't be opened", which has no Open Anyway path at all. A bundle that can lose its seal turns your only onboarding route into a wall.

Fixed in the shared policy module, so both specs get it. Then proved end to end on a real build: 0 __pycache__, --verify --deep --strict exit 0, quarantined verdict back to exit 3, and the packaged app booted from sources alone — health=200, one clean SESSION END.

75% of the homepage and 97% of the guide were invisible without JavaScript

live

Every block carried class="reveal", which is opacity: 0 until an observer fires. Google renders JS; several assistant crawlers do not — and this folder already records that the site appeared in zero of three web searches while an assistant summarising the product quoted the Store copy.

The fix is additive: one rule on html:not(.js) plus an inline head script. With JS present the new rule cannot match, so the animation is untouched. I measured it against the deployed pre-fix site rather than assuming — same reveal count, same initially-hidden count, same per-element delay ladder, same computed transition, 0 hidden after scrolling. No-JS hidden words went 3,125 → 0 and 7,025 → 0.

The inverted form of this fix — hiding on html.js .reveal — would outrank .reveal.vis and nothing would ever be revealed again. That mutant is in the guard.
