Three findings, each of which changed a decision

Title match dominates and the description is only weakly indexed. Credential Manager canvas ranks #9 on a phrase that exists nowhere but our description, while two other description-only phrases return nothing. Writing keywords into the description body is close to worthless.

Panopto, lecture downloader and NotebookLM are uncontested. Everything ranking for them does something else. Cheapest wins available.

Generic download-manager terms were left out on purpose. Ranking blends relevance with download-through rate, so impressions that do not convert teach the algorithm the app is irrelevant. Somebody typing bulk download wants a download manager. Being absent from a term you would lose is not a gap.

Considered and declined: a longer product name

Title match is the strongest ranking field and competitors exploit it (“Video Downloader 4K - Bulk GetVid”). But Microsoft recommends the listing name match the package name, and the package is Canvas Downloader. The app window, Start menu and website would keep the short name while the Store showed a long one. That is brand damage for a ranking bet. Revisit with real search-term data.

Three things to fix in the images first

1. Typos, all the same class. 1_Download2 says “On your pc” and that is slot 1, the most-viewed frame in the listing. 5_Today says “Newest canvas files” and “on your pc.” 4_SyncReview says “what’s on canvas.” Canvas is a proper noun and the product you are naming; lowercasing it in the hero text of a Canvas tool is the one typo this audience notices.

2. Third-party logos in 3_AI_Conversions (NotebookLM, ChatGPT, Gemini, Claude). Showing compatibility is normal and the app genuinely produces files for those tools, but certification can query marks that imply endorsement. Low risk, non-zero. Note how much of that the carousel violates by design: every frame has text and app UI. The hero art cannot be a crop of one of them.

A. The file cascade recommended

A dense, glowing stream of document icons — PDF, PPTX, DOCX, XLSX, MP4 — flowing diagonally out of an abstract glowing portal or cloud on the left, arcing through the centre, pouring into an open folder on the right. Deep brand-blue gradient, the same 3D glass file icons already floating in frames 1 and 5.

It is the product as a picture: many scattered things becoming one organised thing, with no word needed. It reuses the language the carousel established, it is centre-weighted so it survives cropping, and density is easy to hit.

B. The folder shelf

Overhead, slightly tilted, many course folders in neat receding rows, each softly glowing, disappearing into blue depth. Says “all of it, ordered”.

Risk: repetition can read as texture rather than subject, and it is the concept most likely to look like stock.

C. The single folder, opening

One hero folder dead centre, lid lifted, light pouring out, file icons rising and drifting up from it.

Strongest at small crops and closest to the app icon, so it reinforces recognition in a grid of Store tiles. Least informative of the four. Keep as the fallback if A looks busy once the bottom third is dimmed.

D. Before / after split do not use

Chaos on the left, tidy folders on the right, bright seam down the middle. The most persuasive idea, and it fails the crop rule: any centre crop cuts the seam and destroys the point.

Recorded so it is not re-proposed.

Four things to build around

1. Viewers decide in the first 3 to 5 seconds. Do not open on a logo animation or an empty app. Open mid-action, on the thing only this app does.

2. Assume it is watched with no sound. Music carries mood, not meaning. Your text-overlay plan already covers this — hold each overlay longer than feels right while editing.

3. Key information belongs in the centre of the frame. Some Store layouts crop top and bottom.

4. Real captured UI only. No mocked screens, no overlays that misrepresent behaviour.

    Do not click either link on that screen. Remove at the bottom sits directly under the 2.0.2.0 block and removes what you just uploaded. Don’t remove this package keeps 2.0.0.0 alongside the new build, which is how users go on being served the old one.

Make this update mandatory is inert here: Microsoft’s own warning says it applies only to UWP packages, and this is a full-trust Win32 app that makes no Store API calls at all. Roll out update gradually limits blast radius while you watch for a problem, and with no analytics or telemetry there is nothing to watch with — so it is a delay, not a safety net, and one you have to remember to finish. What this update switches on

The in-app rate on the Store card is MSIX-only and ships in v2.0.2. It has never run in the Store build, because the Store build is v2.0.0 and predates it. The listing has 0 ratings after 800+ installs, Store ranking is rating-driven, and nearly every app outranking us in adjacent queries sits between 4.0 and 4.8 stars.

Its gate asks Windows for package identity. That was recorded as unverified in a packaged build. It is verified now, with both controls:

ProcessReturn codeGate answers
Unpackaged system Python (negative control)15700 — APPMODEL_ERROR_NO_PACKAGEFalse
Store-packaged Python 3.11 (positive control)122 — ERROR_INSUFFICIENT_BUFFERTrue

The negative control is the half that matters. A gate answering True for everything would put the card on the .exe build; one answering False for everything would silently never show it. Both are excluded. Still unverified is the card rendering inside a real MSIX container — not a blocker, since the failure mode is one card not appearing.
